# CUTLINE Agent Specification

## Overview

CUTLINE is a release-assurance control plane for agentic cinema. It helps a
post-production supervisor determine whether a VFX sequence will cross a
delivery deadline, retrieve evidence through Grafana MCP, calculate the impact
deterministically, approve one bounded recovery, execute it through an
allowlisted Google Cloud control path, and verify recovery with fresh evidence.

The submission is one controlled synthetic scenario:

- Production: Eclipse Protocol — Episode 6
- Sequence: SQ-42
- Operator: Maya Chen
- Final shots: 18
- Shots initially at risk: 12
- Backlog: 4,800 frames
- Package-lock window: 24 minutes
- Observed throughput before recovery: 120 frames/minute
- Deadline minimum: 200 frames/minute
- Safe target: 240 frames/minute
- Observed throughput after recovery: 320 frames/minute
- Initial projection: 16 minutes late
- Verified projection: 9 minutes early

## Example Use Cases

1. Maya resets the controlled scenario and sees twelve shots projected beyond
   the release cutline.
2. Maya starts an investigation and receives current Grafana MCP evidence for
   the alert, metrics, logs, and trace.
3. Maya expands deterministic deadline arithmetic and validates every result
   from visible inputs.
4. Maya reviews a supported root-cause hypothesis, its strongest alternative,
   discriminator, and falsifier.
5. Maya approves or rejects one allowlisted SQ-42 recovery.
6. CUTLINE executes an approved action exactly once, records its receipt, and
   verifies success only from later Grafana MCP evidence.
7. If MCP, execution, freshness, or verification fails, CUTLINE stops in a
   truthful blocked, failed, or unverified state.

## Tools Required

- Google ADK for agent orchestration and structured tool calls.
- Gemini on Vertex AI for bounded evidence synthesis and explanation.
- Official Grafana MCP for runtime evidence retrieval and post-action
  verification.
- Cloud Run for the hosted UI/API and the allowlisted scenario action.
- Secret Manager for Grafana credentials.
- OpenTelemetry, Cloud Logging, Cloud Monitoring, and Cloud Trace for
  operational evidence.
- A local deterministic Grafana adapter for zero-cost tests. It must never be
  presented as live MCP evidence and must be disabled in submitted live mode.

## Constraints and Safety Rules

- The submission runtime uses Google AI and Google Cloud plus Grafana MCP.
- No arbitrary infrastructure command or model-generated parameter executes.
- Recovery requires a valid, unexpired approval bound to the current run and
  proposal.
- Duplicate approvals or actions are idempotent.
- Stale, prior-run, partial, or malformed evidence cannot verify recovery.
- Gemini does not perform authoritative arithmetic or declare operational
  success.
- Numerical AI confidence is prohibited unless calibrated; the product shows
  evidence status, alternative, discriminator, and falsifier instead.
- Synthetic production assumptions are always labeled.
- Real/live mode cannot silently fall back to local or cached evidence.
- Deployment and billable evaluation require explicit user approval.

## Success Criteria

- Every user-visible feature has a tracker-backed story and test.
- All deterministic in-scope application modules achieve 100% statement and
  branch coverage.
- The full local journey resets and completes five consecutive times.
- A clean browser can understand the sequence, risk, required decision, and
  evidence boundary without narration.
- Pre-action and post-action evidence have distinct timestamps and the same
  active run ID.
- The immutable action chain is visible:
  approval ID → action ID → execution receipt → configuration transition →
  Grafana annotation → fresh verification.
- The app never reports verified recovery unless throughput is at least 240
  frames/minute and all declared stability gates pass.
- The public runtime can be deployed to Cloud Run using only documented Google
  Cloud services after the explicit deployment gate.

## Deployment Choice

- Prototype first.
- Cloud Run deployment target after local feature, audit, and coverage gates.
- Google Cloud Build for CI/CD only after explicit approval.
- In-memory state for the hackathon scenario; run records remain bounded and
  resettable.
